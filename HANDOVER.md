## 1. What the bot is

- **Bot:** @paxorder_bot, display name "Paxyo Order", https://t.me/paxorder_bot
- **What it does:** users order social-media services (followers, likes, views, comments, subscribers) by chatting — text AND voice, in Amharic or English. First-time chatters get a Paxyo account auto-created on /start.
- **Money rule (owner's core rule):** "the AI only listens and talks. All money steps are deterministic code." The server computes all totals; the AI never sets prices.
- **Fulfilment:** Paxyo talks to the provider GodOfPanel (godofpanel.com) via paxyo.et. **The bot NEVER talks to GodOfPanel directly, and must NEVER reveal GodOfPanel to users, never reveal what Paxyo pays for services, and never call it an SMM panel service.** Only Paxyo selling prices are shown. If asked about provider/source/cost, deflect politely without confirming or denying.
- **Pricing:** Paxyo sell price = provider rate × **420 ETB** (confirmed by William; NOT ×400). Owner buys 1 USD for 200 ETB, sells at 420, profit 220 ETB per 1 USD. The 420 multiplier is editable in Paxyo Settings.
- **Blacklisted services, permanently:** **5379 and 5834** — never sell them, never surface them in cheapest-first lists.
- **Customer bot vs admin bot:** customer bot is @paxyo_bot; admin bot is @paxadmin_bot (owned by Abel, NOT part of this project). This project is ONLY @paxorder_bot.

## 3. The Paxyo Bot API (on paxyo.et)

Built on paxyo.et (PHP + live MySQL), NOT on Abel's Render backend. File: `public_html/api/bot.php` (+ `.htaccess` rewrite `api/bot/(.*)` → `api/bot.php?bot_path=$1`).

- **Auth:** header `X-Bot-Secret`, value is `BOT_API_SECRET` stored in `config_secret.php` on the server. **Value never recorded anywhere — never put it in chat, git, memory or files.**
- **Rate limit:** 30 requests/min per telegram_id (verified: 35 rapid calls → 28×200 then 7×429).
- **Endpoints (all verified live):**
  - `GET /api/bot/services` — 7,176 services, price in ETB per 1000, rate_multiplier 420, fields: id, provider_service_id, name, category, type, price, currency, min, max, average_time, active. Blacklisted services listed with active:false. Service 429 sold as 9875 ("30 Days" → "Lifetime") at flat 13.20 ETB/1000.
  - `GET /api/bot/balance?telegram_id=` — balance in ETB.
  - `POST /api/bot/orders` — validates account/service/link/quantity (multiple of 10, min/max), refuses blacklisted (403) and disabled services, holiday discount, server-side total, atomic balance debit, provider order via GodOfPanel, **idempotency_key (UNIQUE column on orders)** — duplicate key returns the earlier order with `duplicate:true`, no second charge.
  - `GET /api/bot/orders/{id}?telegram_id=` — by local id or provider api_order_id, scoped to user.
  - `GET /api/bot/orders?telegram_id=&limit=` — history, newest first, max 20.
  - `POST /api/bot/users` — auto-create on /start: {telegram_id, username, first_name} → created true/false. Identity: `auth.tg_id` IS the Telegram ID.
  - Recurring: `POST /api/bot/recurring` (interval_minutes ≥ 30), `GET /api/bot/recurring`, `POST /api/bot/recurring/{id}/cancel|pause|ran`, `GET /api/bot/recurring/due` (secret-only). Table `recurring_orders`.
  - Deposits: `POST /api/bot/deposits` (Chapa Direct Charge / USSD push), `GET /api/bot/deposits/{id}` (re-verifies with Chapa; credit once only on amount match; failed/rejected/cancelled or >48h still-pending → Failed), `GET /api/bot/deposits` list. Min 10 ETB, max 100,000 ETB. Method/phone stored as JSON in `chapa_response` (deposits table has no method/phone columns).

## 5. What the bot can do (behaviour, all tested)

- **Ordering:** intent classification → service pick (fastest by average time, or user-named service via service ID) → Confirm card (service/quantity/link/total) → place → summary. **No order without an explicit Confirm tap — EXCEPT urgent "please order now"** (owner override, round 5: explicit phrases only, places at once, full summary after).
- **Short names only** when showing services for selection; full/long name ONLY when the user entered a service ID.
- **Price questions answered directly** — never ask for the link first. Budget answers state quantities (e.g. "10 birr ≈ 520 TikTok views").
- **Speed questions:** real estimate from the pending/fastest service's average time + "sooner we place it, sooner it completes — let's order now". The vague "shown before you confirm / varies by service" wording is gone.
- **Reply-to recognised:** replying "1000" to "How many?" works; "yes" to a Confirm card confirms.
- **Memory:** last ~10 exchanges/user, persisted to chat_history.json (Render free disk is ephemeral on redeploy). "Same as usual" reuses last service + link + quantity. "Same as yesterday but double" caps at max.
- **Edge cases (owner spec, 13 Nov 16:26):** "the usual"; "boost my latest video" (ask for link); budget-first; goal-based (ask which metric); split across N posts (one Confirm places all); multi-service single message (batch Confirm); drip-feed = recurring ≥30 min (<30 refused in one line); friend's typo'd handle (exact handle on Confirm); platform mismatch (flagged, NEVER placed mismatched); shortened links accepted; private/expiring links (one warning on Confirm, never rejected); mid-order change/cancel (draft editable/cancellable, placed = show status); impatience (real status + average time, never "soon"); short delivery (status first, NO refill/refund promises); receipt screenshot mid-order → deposit recheck, half-built order survives; split payment NOT supported (deposit first); reverse-calc quantity from balance; NO discount negotiation; NO geo-targeting; NO free trial (cheapest service suggested); prompt injection on price ignored; caption/posting-time tips brief OK; website problems → support redirect.
- **Ban/shadowban question:** answer NO — "anybody can buy followers for you, so your account can't be banned or shadowbanned for it without your permission" (William's answer, supersedes the old no-zero-risk line).
- **"Real Ethiopian followers":** global network, never overpromise.
- **Terms:** refunds ONLY to Paxyo balance (never bank/mobile money), balance cannot be withdrawn as cash, orders cannot be cancelled/modified once processing starts, accounts must be public, results not guaranteed permanent, drops may occur. Source: paxyo-terms.md.
- **Payments accepted:** Telebirr, CBE Birr, CBE, M-Pesa. First-deposit bonus 20% with invite code REF3723FB335. Bot must remind users the account must NOT be private (on every Confirm card).
- **Deposits by chat:** Confirm card first, then Chapa USSD push (method + amount + phone only). If push fails → checkout-link fallback (pending the Chapa decision in §3). Deposit recheck: user says "I paid" or sends a receipt screenshot → bot re-verifies with Chapa, reports paid / still waiting / failed, never invents a reason.

- **Photos:** bot reads uploaded pictures (payment screenshot, profile screenshot, error screenshot) via vision, 10 MB cap, bytes in memory only.
